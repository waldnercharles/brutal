# arch_ecs.h Parallel Iteration Design

## Goal

Add `ecs_parallel_for` to arch_ecs.h — parallel entity iteration using a pluggable thread pool. No system scheduler, no groups, no dependency tracking. Just parallel loops.

## API Surface

### Setup

```c
typedef int (*ecs_enqueue_fn)(int (*fn)(void *), void *arg, void *udata);
typedef void (*ecs_wait_fn)(void *udata);

// Configure once on ecs_world
void ecs_set_threads(ecs_world *w, ecs_enqueue_fn enqueue, ecs_wait_fn wait,
                     void *udata, int max_tasks);
void ecs_set_min_entities_per_task(ecs_world *w, int min_count);
```

Stored on `ecs_world`. Compatible with any thread pool (tpool.h, custom, etc).

### Task Struct

```c
typedef struct ecs_task ecs_task;
struct ecs_task {
    void (*fn)(ecs_task *);
    ecs_world *w;
    int n;            // entity count for this slice
    int *entity_ids;  // entity IDs (for kills)
    int task_index;
    // Per-component SoA pointers (generated by ECS_COMPONENTS macro):
    // Position *position;
    // Velocity *velocity;
    // Health   *health;
#define ECS_TASK_PTR_(T, f) T *f;
    ECS_COMPONENTS(ECS_TASK_PTR_)
#undef ECS_TASK_PTR_
};
```

Component fields mirror the archetype layout — named, typed, direct access. Pointers are pre-offset to the slice start. NULL for components not in the archetype.

### System Functions

```c
// Pure transform
void move(ecs_task *t) {
    for (int i = 0; i < t->n; i++)
        t->position[i].x += t->velocity[i].vx;
}

// With kills
void cleanup(ecs_task *t) {
    for (int i = 0; i < t->n; i++)
        if (t->health[i].hp <= 0)
            ecs_kill_id(t->w, t->entity_ids[i]);
}
```

### Dispatch

```c
ecs_parallel_for(&world, move, Position, Velocity);
ecs_parallel_for(&world, cleanup, Health);
```

Macro computes component mask from type names, walks matching archetypes, splits entities into task ranges, enqueues, waits, flushes kills. Falls back to single-threaded if no thread callbacks configured.

### Kill helper

```c
static inline void ecs_kill_id(ecs_world *w, int id) {
    ecs_kill(w, (ecs_entity){ .id = id, .gen = w->entities[id].gen });
}
```

## Threading Model

### Dispatch Flow

For each matching archetype:
1. Compute `task_count = min(arch->count / min_per_task, max_tasks)`, clamped to `[1, max_tasks]`
2. Split `[0, arch->count)` into `task_count` ranges
3. Build `ecs_task` struct per range:
   - Set `fn`, `w`, `n = end - start`, `entity_ids = &arch->entity_ids[start]`, `task_index`
   - For each component in archetype mask: set `task.field = &arch->field[start]`
   - Non-matching components: NULL
4. Enqueue all tasks via `w->enqueue`
5. `w->wait` — blocks until all tasks complete
6. Flush kill lists (see below)
7. Move to next archetype

Task storage: `ecs_task par_tasks[ECS_MT_MAX_TASKS]` on `ecs_world`.

### Trampoline

```c
static _Thread_local int ecs_tls_task_index_;

static int ecs_par_trampoline_(void *arg) {
    ecs_task *t = arg;
    ecs_tls_task_index_ = t->task_index;
    t->fn(t);
    return 0;
}
```

### Fallback

If `w->enqueue == NULL`, run all tasks sequentially on the calling thread.

## Kill-During-Parallel-Iteration

### Why No Atomics

Each entity occupies exactly one row in one archetype. Task ranges are non-overlapping slices of archetype rows. Therefore, each entity is processed by exactly one task — no contention.

### Per-Task Kill Lists

```c
#ifndef ECS_MT_MAX_TASKS
#define ECS_MT_MAX_TASKS 64
#endif
#ifndef ECS_MT_KILL_LIST_SIZE
#define ECS_MT_KILL_LIST_SIZE 256
#endif

// In ecs_world:
bool par_iterating;
int par_kills[ECS_MT_MAX_TASKS][ECS_MT_KILL_LIST_SIZE];
int par_kill_counts[ECS_MT_MAX_TASKS];
```

### Kill Path (modified ecs_kill)

```c
if (w->par_iterating) {
    info->gen++;
    int task = ecs_tls_task_index_;
    assert(w->par_kill_counts[task] < ECS_MT_KILL_LIST_SIZE);
    w->par_kills[task][w->par_kill_counts[task]++] = e.id;
    w->alive_count--;  // single-writer per entity, no contention
    return;
}
```

No `deferred_dead` needed during parallel iteration — each entity is processed by exactly one task. A killed entity won't be revisited. Other tasks can't observe it.

### Flush (after wait, on main thread)

```c
static inline void ecs_par_flush_kills_(ecs_world *w) {
    for (int t = 0; t < ECS_MT_MAX_TASKS; t++) {
        for (int k = 0; k < w->par_kill_counts[t]; k++) {
            int id = w->par_kills[t][k];
            // swap-remove from archetype (same as existing ecs_kill non-deferred path)
            ecs_entity_info *info = &w->entities[id];
            ecs_archetype *arch = &w->archetypes[info->archetype];
            int row = info->row;
            int last = arch->count - 1;
            if (row != last) {
                // swap-remove component data + entity_ids
                // update swapped entity's row
            }
            arch->count--;
            info->archetype = -1;
            w->free_list[w->free_count++] = id;
        }
        w->par_kill_counts[t] = 0;
    }
}
```

## World Struct Additions

```c
typedef struct {
    // ... existing fields ...

    // Threading callbacks
    ecs_enqueue_fn enqueue;
    ecs_wait_fn wait;
    void *task_udata;
    int max_tasks;
    int min_entities_per_task;  // default: 64

    // Task storage
    ecs_task par_tasks[ECS_MT_MAX_TASKS];

    // Per-task kill lists
    bool par_iterating;
    int par_kills[ECS_MT_MAX_TASKS][ECS_MT_KILL_LIST_SIZE];
    int par_kill_counts[ECS_MT_MAX_TASKS];
} ecs_world;
```

## Macro Implementation (ecs_parallel_for)

```c
#define ecs_parallel_for(world, fn, ...) \
    ecs_parallel_for_((world), (fn), ECS_TMASK_ALL_TYPES(__VA_ARGS__))
```

Where `ecs_parallel_for_` is a static inline function... except it needs to fill component pointers by name, which requires macro expansion. So the dispatch logic is a macro that:

1. Computes mask via `ECS_TMASK_ALL_TYPES`
2. Walks archetypes inline
3. Fills task structs using `ECS_COMPONENTS(ECS_PFILL_)` to set each component pointer:
   ```c
   #define ECS_PFILL_(T, f) \
       ECS_P_(w)->par_tasks[_t].f = \
           (_arch->mask & ECS_MASK(f)) ? &_arch->f[_start] : NULL;
   ```
4. Enqueues via trampoline, waits, flushes

## Interaction with ECS_FOR

- `ECS_FOR` — single-threaded, inline body, supports kills (deferred), break/continue
- `ecs_parallel_for` — multi-threaded, callback function, supports kills (per-task lists), no break/continue

Both set `w->iterating` / `w->par_iterating`. They should not be nested.
